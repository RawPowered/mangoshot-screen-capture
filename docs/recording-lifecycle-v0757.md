# MangoShot v0.7.57 - Recording Lifecycle (development preview)

## Installation
The cumulative overlay is for v0.7.55 Render Integrity Hotfix (52200e606a60aff21d9dddd03b412575c7c9a3bc) or its v0.7.56 Core Integrity Pass 1 derivative. Back up the complete unpacked extension and save important recordings/projects. Replace the overlay's relative paths in the SAME extension folder, then reload the extension. Reload linked source webpages so they receive the updated content script. No change to extension ID or existing IndexedDB schema. Native Rust source is included, not a compiled or signed native companion. The previous native host remains compatible, but disconnects on pause; install only a separately qualified compatible v0.7.57 Windows native host to activate seamless native pause/resume.

## Recording integrity
- Recording clock, cursor samples, pause compensation and capture summaries use one monotonic clock.
- Recording fragments retain periodic cursor checkpoints (approximately every five seconds when encoded data is flushed); checkpoint and matching video chunk are stored atomically in one transaction. Recovery refuses missing video fragment indices. Interrupted recordings no longer discard the last valid stored telemetry checkpoint.
- Recovered video is independently decoded. Its cursor history is clipped to the actual decoded duration and the stored checkpoint boundary, never extended from wall-clock estimates. A terminal path gap and retention-off state stop inferred movement/effects after the checkpoint. Automatic camera reconstruction is withheld for incomplete telemetry; camera history remains available. Interrupted MP4 may still be undecodable.
- Every partial or recovered handoff has its own ID; a later complete recording cannot replace the partial media under the editor. An encoder error is not treated as successful finalization. Recovery/clear actions are blocked during active capture.
- Modern native host advertises pause_resume. The browser keeps the same authorized monitor lease while pausing, drops in-flight data, waits for acknowledgements, and revalidates monitor identity and source generation on resume. The host stops reading pointer positions while paused, removes overlays/hotkeys, and re-registers them only after resume. A timeout, identity mismatch, host disconnect, or unsupported capability fails closed. Legacy hosts safely require reconnect.
- Linked-tab tracking uses ordered pause/resume generations and rejects stale events. Navigation or revocation still disconnects; an old injected script requires reconnect. Pausing does not collect pointer events on the source page.
- Canceling a monitor picker leaves the original recording and tracking connection intact. Committing a new source terminates the old tracking lease, inserts a gap and requires explicit matching-source consent. There is no passive auto-attachment to a different monitor.

## Qualification
The focused JavaScript model/harness checks cover monotonic-gap behavior, recovery bounds, safe native pause/resume, stale sample rejection, legacy fallback, rapid resume and monitor mismatch. Native Rust code requires Windows compilation and hardware testing. Actual MediaRecorder timing, audio continuity, IndexedDB storage failure/reload, source picker, linked-page integration and encoded output must be tested in a real browser. No stable release or production certification.

Manual acceptance: record an authorized clean master; pause for several seconds, move pointer while paused, resume, verify no paused samples; cancel and complete a monitor switch; reconnect explicitly; stop and open exact recording; induce an interrupted WebM session, recover checkpoint, verify missing tail is not recreated; test MP4/WebM and source audio; save/reopen the project; confirm last known good overlay still works. See docs/core-integrity-v0756.md for Pass 1 limitations.
