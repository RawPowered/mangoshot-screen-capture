# MangoShot v0.7.1 — Editor viewport and precision-tool acceptance

Patch B.1 is an **unreleased development preview**, layered on Patch B and Patch A.

## User-visible behavior

- Both editors occupy the browser viewport, not a vertically scrolling web document.
- Image Studio's canvas stage has **no scrollbars**. Fit uses both image dimensions and available stage width/height. For magnified images use Space + left drag or middle drag to pan; Alt + mouse wheel changes zoom around the pointer.
- Tool rail is compact: Select, Drawing, Erasers, Shapes, Redaction, Text, Masks. Click the main icon to invoke the remembered tool; click the chevron or right-click / stylus barrel-click to choose a variant. All original tool button identities and handlers are preserved.
- Tool variants show original SVG icons and textual labels. Flyouts respond to Escape and Up/Down keyboard navigation.
- Tool-sensitive SVG mouse cursors are generated **locally** and have defined 32x32 hotspots: arrow at (3,2), pen at (5,27), geometric targeting and brush rings at (16,16). The visible eraser ring follows brush-size and image zoom, capped to the cursor viewport.
- Clip Studio timeline Razor and Range cursors update with the selected tool; trim handles retain directional resizing cursors.
- The Properties panel, saved workspaces, keyboard shortcuts, Wacom input, existing editing transactions, and project data remain owned by previous systems.

## Manual acceptance — must pass before stable release

| Environment | Required checks |
|---|---|
| Windows Chrome and Edge, 1920x1080 and 1366x768 | No document scrollbar; stage and timeline fit; menu accessible; tool flyouts and Property controls remain usable |
| Firefox 128+, 1280x720 | SVG cursor or documented fallback; menu/rail/toolbar and dialog access; no page scroll |
| Short desktop window 1024x600 | No document scroll; side inspector and Media Library scroll internally; no unreadable or unreachable flyouts |
| Tablet portrait and landscape | No body scrolling; inspector appears as overlay, not an offscreen panel |
| Image full-page 1920x12000 | Fit displays whole image; 100% + pan exposes offscreen detail; export remains full resolution |
| Wacom pen and eraser | Pen cursor is precise, tip hotspot correct; pressure/eraser behavior unchanged; right-click or barrel-click opens tool variants |
| Image tools | Every rail category selects correct underlying tool; shortcuts still update active icon; vector variants remain editable |
| Clip Studio | Select/Razor/Range hit targets and trim handles show correct cursor; cut, trim and playback unchanged |
| Canvas interaction | Space+drag and middle-drag never draw a stroke or select unintended layers; typing with Space in text fields remains possible |
| Accessibility | Escape closes flyouts; keyboard focus and aria-pressed state remain coherent; buttons have named tool labels |

Browser QA must measure `document.scrollingElement.scrollHeight <= window.innerHeight + 2` at the specified dimensions **except during browser zoom accessibility testing**, where controls must remain reachable through internal panel scrolling or adaptive layout.

## Technical safety gates

- Run `for test in tests/*.cjs; do node "$test"; done`, plus JavaScript syntax checks and extension ZIP integrity.
- Unit tests inspect SVG cursor bounds, hotspot offsets, local data URIs, source-tool retention, viewport CSS and HTML wiring.
- Do not relabel the manifest as v0.7.1 until a signed/stable release is actually prepared. This branch still uses manifest 0.6.18 for preview compatibility.
- Do not claim the browser extension has passed physical Wacom or visual QA solely from GitHub Actions.
