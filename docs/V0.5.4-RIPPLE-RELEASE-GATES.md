# MangoShot v0.5.4 — sequence editing repair

## Problem and scope

Razor could create V1 segments but Ripple Delete required manually entering In/Out numbers. Clicking a V1 clip did not make it an actionable edit selection, and graphics, markers, video and undo were not committed as one transaction. Trimming V1 edges moved the video and graphic timing but did not consistently update marker positions. A range could not be selected directly on the ruler.

This pass preserves the v0.5.3 recorder, audio, PNG/PDF screenshot, Wacom and layered export modules unchanged. Editing remains non-destructive. The actual encoding pipeline and accuracy limits are unchanged.

## Changes

1. `sequence-operations.js`: pure, deterministic sequence-time operations for ripple-delete selected clip, ripple-delete range, trim to range, and inward edge trim. All return video segments, graphic clips, markers and new playhead time. The source media is never altered.
2. V1 clip click selects a specific segment, highlights it, and enables contextual Ripple Delete. Use a range created by Shift+dragging the ruler or by activating the **Select range** tool; a translucent range band shows the exact deletion span.
3. `Ripple delete` toolbar and `Ripple delete clip / range` inspector action use one transaction. No selection produces an actionable explanation; deleting the sole remaining clip is rejected.
4. Edit history includes markers, selected video clip, selected graphic, range and In/Out fields. Ctrl+Z undoes; Ctrl+Shift+Z or Ctrl+Y redoes. Creating timeline markers itself is undoable.
5. V1 inward trim handles apply the same downstream ripple to graphic and marker timing. When a selected clip is active, Trim to Selection works on that clip.
6. More informative timeline selection status; `R` enables Range Tool, `V` selects, `C` Razor, and Delete or Alt+Backspace acts on the current selection (a selected graphic takes precedence for plain Delete).

## Validation completed locally

- `node tests/sequence-operations.cjs`: pure V1 clip deletion, range deletion, trim, edge trim, marker/layer shift and immutable source.
- `node tests/clip-studio-mock.cjs`: real editor state V1 selection + Ripple Delete + Undo/Redo + range deletion, preserving layers and markers.
- `node tests/clip-timeline-ui.cjs`: pointer-based ruler range tool, Shift+drag selection, zoomed ruler scrubbing, dispatch to editor.
- Existing screenshot, PNG/PDF, recorder, Wacom, video, project and graphics suites.

## Device-level acceptance required before merge

1. Import a >90-second video. Razor at two interior times to get three V1 clips, click the middle clip, Ripple Delete, confirm the gap closes and edited playback uses the next source frame.
2. Add title and callout spanning that removed section plus a marker before and after. Confirm timing changes visibly and Undo/Redo returns precise original timing.
3. Shift+drag from 00:20 to 00:30 on ruler; preview highlighted region, Ripple Delete, verify 10 seconds removed and no unrelated clip is deleted.
4. Repeat deletion after Generate Thumbnails and Analyze Waveform (where audio is present), at zoom 1x, 3x and 6x, with mouse and Wacom pen.
5. Test controls in Firefox, Edge and Chrome on Windows. Export MP4 where browser encoder genuinely supports it; otherwise WebM. Validate audio, length and final frame.
6. Confirm no regressions in visible/full screenshots, video Stop and recording recovery.

## Known limitations

- Browser-native MediaRecorder export re-encodes edited footage at approximately playback speed; cuts are sequence-time accurate but not guaranteed frame-exact packet edits. Universal offline MP4 encoding remains unimplemented.
- An empty V1 sequence is rejected; use Import Video or Restore Full Source rather than deleting all footage.
- Source videos with no audio stream cannot display a waveform.
- Browser automation of the actual unpacked extension and Windows Wacom hardware was not available in this authoring environment.
