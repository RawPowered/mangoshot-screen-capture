# MangoShot v0.7.7.2 — ChatGPT Tunnel development preview

Based on the qualified 0.7.7.1 permission hotfix. Required nativeMessaging stays as before in this separate bridge-enabled preview; no new browser permissions or remote listener. This preview adds a guided ChatGPT setup panel in Clip Studio > Automation > Intelligence Bridge and a local interactive launcher in the Windows companion. It does not create OpenAI resources, download executables, install a ChatGPT plugin, store keys, or enable remote editing automatically. The operator must authorize all steps locally.

## Upgrade the working local pair

1. Save/export work, disconnect, close all MangoShot Clip Studio pages and stop any old MCP/tunnel processes.
2. Replace the existing unpacked extension files with the new extension ZIP contents. Keep the same directory and browser extension ID. Reload in edge://extensions or chrome://extensions. Build identifier: 0.7.7.2 ChatGPT Tunnel preview; numerical manifest version remains 0.6.18.
3. Extract the matching Windows companion package. Close any still-running MangoShotBridge.exe process before updating. From PowerShell in the extracted folder, run the included install-windows.ps1 with -EdgeId or -ChromeId and your exact extension ID. If your existing native manifest already points to the default installed executable, the installer updates that executable without changing the origin. No administrator or policy bypass. The preview is unsigned; inspect source and obtain only from the verified project build.
4. Open a video, choose 15, 30 (default) or 60 minutes and the desired scopes, then Pair. The panel displays the companion version. The 30-minute mode remains compatible with the old native host, but the new launcher and modern MCP protocol require the new companion.

## ChatGPT setup

Use OpenAI's official Secure MCP Tunnel, not a public port forwarding service. Open https://platform.openai.com/settings/organization/tunnels . Create or choose a private tunnel associated with the intended ChatGPT workspace, and a restricted runtime API key with Tunnels Read + Use. Creating tunnels requires Tunnels Read + Manage. Keep admin keys separate. Obtain the full official tunnel-client executable from the Platform download or https://github.com/openai/tunnel-client/releases/latest ; verify release provenance/checksums before executing it. No automatic third-party binary download or bundled tunnel-client. The launcher uses the standard polling tunnel setup; other provisioning/network configurations may require the official client directly.

In MangoShot's new Connect to ChatGPT panel, select the launcher command and run it in a local PowerShell:

    & "$env:LOCALAPPDATA\MangoShot\Bridge\MangoShotBridge.exe" --connect-chatgpt

Enter the full official tunnel-client executable path, the tunnel ID, pairing port, pairing token (hidden), then runtime API key (hidden). Never send those secrets to ChatGPT or paste them into shell commands. The token is in Reveal pairing configuration. The wizard first checks the authenticated local pair using a health probe that cannot bind the client slot. It refuses an already bound client; re-pair. On explicit confirmation it starts the official client in the foreground with a fresh temporary configuration containing only nonsecret settings and an environment reference for the API key. Tokens travel in the child environment, not argv/files. Same-user processes are not a strong secrecy boundary. No permanent environment variables. No raw HTTP logging. Existing profiles and unrelated environment overrides are not inherited. Explicit selection of the trusted binary is required. No system-wide service or auto-start.

When the launcher reports READY, go to ChatGPT Plugins > + > Add custom MCP server, select Tunnel, choose the tunnel ID, configure authentication according to your workspace, acknowledge the risk warning and create the private plugin. Admin/owner or authorized developer privileges may be required. Do not publish broadly: all authorized callers of the same tunnel share its one local MCP child and the selected scope. Test list_commands and inspect_project with metadata scope enabled. Only then consider the ChatGPT connection verified. MangoShot shows observed MCP tool activity, not a verified identity of ChatGPT. The official client readiness check uses a loopback-only /readyz URL. No remote health listener. Raw child diagnostics are not logged by the wizard; if needed, use official client diagnostics locally and avoid exporting sensitive logs. Keep the console and paired editor open. Ctrl+C stops the launcher; expiry/disconnect also ends access and stops the supervised tunnel on health failure. Re-pair before restarting a client. Stop an earlier tunnel instance first.

## MCP contract

The adapter retains legacy initialize/notifications/initialized and adds 2026-07-28 self-contained stdio discovery and tool requests using protocolVersion/clientCapabilities in params._meta. Modern results include resultType complete and serverInfo metadata. Tool listing is private/noncacheable and annotations distinguish reads from proposal/frame requests and one-shot status retrieval. Only the five existing tools are exposed. No direct application, arbitrary code, shell or file access. Local health is not an MCP tool. No weakening of source/revision binding, approvals or frame disclosure. MCP calls may be served through the official tunnel; approved information can leave the computer only within the explicitly authorized scopes, and frame content still requires separate approval.
