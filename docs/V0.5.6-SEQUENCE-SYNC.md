# MangoShot v0.5.6 — Sequence media synchronization and performance qualification

## Core invariant

V1 segments are non-destructive records with `start` and `end` times measured on the source file. The editing ruler, thumbnail strip, G2/G3 graphics and A1 audio waveform are **sequence time** (the sum of retained clip durations). `sequence-media.js` is the sole mapping between these coordinate systems.

At a cut at output time `t`, the next source segment owns `t`. A deleted source section must never contribute a thumbnail or audio peak to output time.

### Thumbnails

`clip-timeline-ui.js` samples at uniformly spaced **sequence** positions, maps each to a retained source frame, and labels the result with both times. It retains decoded thumbnails in a bounded per-source cache. Editing immediately remaps compatible thumbnails and fills the rest with honest placeholders; a deferred background scan fills the missing positions. It never reuses a frame across a cut if that frame belongs to a deleted source interval.

### Waveform

The local audio analysis caches a compact envelope from the source. Every timeline re-render computes `A1[x]` from the retained source ranges corresponding to output pixel `x` and draws cut markers. The same peaks are reused across Undo, Redo and AutoCut. This does not generate audio if none exists, and some browser decoders cannot decode MP4/WebM audio with `decodeAudioData`.

### Edited Program Monitor

`sequence-preview.js` drives the visible video element through retained source ranges with native video/audio sync. At an edit point it pauses, seeks to the next source segment and resumes. The normal transport Play and Play Edited Sequence use the same controller. Clicking or wheel-scrubbing to a new sequence position stops the old playback. `requestVideoFrameCallback` is preferred where supported, with animation-frame fallback.

This is a **real-time decoder preview**, not a completely pre-rendered media file. Seek latency and frame boundaries vary by browser/source codec. The renderer must be qualified against actual exported media before claiming frame-accurate cuts.

## Performance profiles

| Setting | Balanced | High-performance |
|---|---:|---:|
| Thumbnail limit | 36 | 80 |
| Waveform input cap | 130 MB | 700 MB |
| Waveform analysis bins | 6,500 | 16,000 |
| Browser export canvas limit | 16 MP | 33 MP |
| Browser capture frame rate | 30 | 60 |
| Browser target bitrate | 4.5 Mbps | 10 Mbps |

**High-performance is not an accelerated render mode.** MediaRecorder receives a real-time video canvas stream and audio stream, so increasing `playbackRate` to shorten wall-clock export would alter the output's duration/audio and is not used. Video bitrate is a target, not guaranteed quality. A future browser-native WebCodecs + muxer engine is needed for cross-browser accelerated non-real-time compositing.

## Optional faster desktop output

`tools/fast-render.mjs` runs on the user's own computer with Node.js and installed FFmpeg. It reads a saved MangoShot JSON project, validates the matching original video, constructs `trim/atrim/concat` filters in **source time**, and exports synchronized MP4 with optional hardware H.264 encoding. It may run faster than real time depending on CPU/GPU, disk and media complexity. A short synthetic run in the authoring environment encoded 2.5 s of retained A/V in about 0.19 s, not a general benchmark.

It **deliberately refuses** visible text and callout layers, which require the browser compositing path for now. It will not overwrite an existing file. Nothing is uploaded; no binaries are bundled.

## Device acceptance tests

1. Record a clip with intentional 2–4 s gaps and clearly identifiable speech/video at boundaries. AutoCut 6+ gaps. Inspect thumbnails and waveform: the positions after each cut must reflect edited sequence time, not original absolute source time.
2. Click Play on the Program Monitor. It must move through retained clips in order without lingering in removed segments. Drag playhead to exact cut and verify the first retained frame from the new segment.
3. Undo AutoCut. Thumbnails and waveform should revert without needing to manually regenerate A1. Redo and repeat with Razor/Ripple Delete and timeline zoom.
4. Check video-only MP4: report no waveform; do not fabricate audio. Check a WebM recording with microphone: A1 alignment and playback must match retained sequence.
5. Export 15–60 seconds with edits. Probe MP4/WebM with ffprobe: correct approximate duration, playable video, audio present when source had it, no silent section retained unintentionally.
6. Test both performance profiles on a Windows desktop. Watch memory/CPU and try 1080p and 4K media. High mode might increase memory and GPU usage substantially.
7. Save project JSON and use optional FFmpeg helper on a cuts-only project. Verify speed/duration and audio. Confirm a project with visible graphics is rejected without exporting incorrect video.
8. Retest screenshot PNG/PDF, recorder stop/recovery, Wacom ink, and Firefox/Chrome/Edge compatibility. Do not merge to stable until these pass.
