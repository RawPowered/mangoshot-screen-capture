# MangoShot v0.7.6 — MangoScript Sequence Engine (development preview)

Based on qualified Automation Studio v0.7.5. The Sequences tab is in Clip Studio > Automation. This is a bounded, declarative JSON language, not arbitrary JS. Existing single-command automation in Image/Record Studio remains unchanged. No new browser permissions, external MCP transport, native companion, release tag or manifest bump.

## Grammar and examples

The envelope uses schema mangoshot.sequence.recipe.v1. Optional name, variables (scalar strings/numbers/booleans, up to 32), functions (up to 12 named reusable step blocks, no recursion), and required steps. Each step is either a registered Clip Studio command with args and optional as result name, a call to a named function, or if/then/optional else using allowlisted hasCursorPath, hasGraphics or minDuration conditions. References are explicit objects {"var":"name"} or {"ref":"step.id"} (also .duration/.count). No evaluation of strings, loops, dynamic property paths, networking or code imports. References are resolved in order; duplicate aliases and invalid IDs fail. Up to 40 executed commands, 100 declared steps, 160 expanded instructions, 32 KiB JSON, bounded nesting. Only eight existing Clip Studio commands are supported. Named functions reuse blocks without parameters; they share program variables and result names.

~~~json
{
  "schema": "mangoshot.sequence.recipe.v1",
  "name": "Tutorial intro",
  "variables": {"title":"Step 1","zoom":2},
  "functions": {
    "intro":[
      {"command":"clip.graphics.add","as":"title","args":{"kind":"text","text":{"var":"title"},"start":0,"duration":3,"preset":"title"}},
      {"command":"clip.graphics.opacity","args":{"id":{"ref":"title.id"},"value":0.9}}
    ]
  },
  "steps":[
    {"call":"intro"},
    {"if":{"test":"hasCursorPath"},
     "then":[{"command":"clip.cursor.effects.add","args":{"start":0,"end":3,"style":{"spotlight":true,"ring":true}}}],
     "else":[{"command":"clip.camera.zoomRange","args":{"start":1,"scale":{"var":"zoom"},"x":0.5,"y":0.5}}]}
  ]
}
~~~

## Planning and transactions

Planning uses a private snapshot of the primary source edit decisions. Commands validate via the shared registry and apply to the draft in order. Later commands see earlier draft changes. Final validation uses the existing portable project, camera and cursor contracts. No mutation before explicit apply. Preview ticket is bound to source object, current state/revision, cursor trace and voiceover identity, expires after five minutes and is consumed once. Editing or closing the review cancels it. Commit validates again, then installs the complete draft as one undoable transaction. On synchronous commit/refresh failure restore the previous snapshot and undo/redo stacks; if interface refresh fails a second time report the limitation. This is an in-memory editor transaction, not crash-safe disk journaling.

All times for add/cut/zoom are edited sequence seconds except existing cursor-region update source times. Ripple uses existing sequence operations and reconciles transitions and source-anchored cursor effects. For safety this iteration requires ripple cuts before camera events exist and disallows ripple when recorded voiceover exists. A sequence may add camera edits after cuts. Existing recorded voiceover is preserved unchanged. Text/layer bounds match portable project contract (400 characters, 200 graphics). Existing V1/V2 media staging and project save behavior remain; no multi-source composition.

## Review

Visual before/after timeline shows retained clips, graphics, camera transition events and cursor regions, on the same scale. Render Frame decodes a separate local video object at a requested planned sequence time and uses existing camera/transition/cursor/graphics renderers, scaled to at most 960x540. It does not seek the original program monitor, upload, encode, play audio, or render an entire preview clip. No permission or native desktop hook. Temporary decoder/object URL is disposed on completion, cancellation and pagehide. Audio and full output parity still require manual tests.

Save up to eight named in-memory checkpoints for the current source. Restore is a new reviewed, undoable visual-edit transaction. Checkpoints exclude the source bytes and recorded voiceover; source replacement removes access to prior points, and changed voiceover blocks restore. No cross-session revision persistence. Operation history is session-only, up to 100 entries, contains program names/status/time but no bodies or media. Sequence import/export is explicit JSON; loading never executes. No new shared recipe library support for multi-step recipes yet.

## Qualification gates

Pure planner tests cover variables, conditions, references, recursive/oversized/invalid instructions, rollback-by-no-mutation on a failed later step, stale tickets, checkpoint source binding. Real editor model tests exercise grouped apply/undo/redo, checkpoint restore and injected render error rollback. Chromium smoke imports generated six-second WebM, verifies decoded preview pixels, no original playhead movement, batch and checkpoint commits, undo and short viewport dialog. Existing v0.7.5 tests remain. Real user media/export, Firefox/Edge, physical Wacom, full render playback and native/MCP connection are not certified by this build. Future companion must pair explicitly and request reviewed application; no remote endpoint exists.
