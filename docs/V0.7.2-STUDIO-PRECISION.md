# MangoShot v0.7.2 — Studio Precision (development preview)

## Scope and invariants

This patch is an incremental UIX foundation, not a new stable release or a rewrite of either editor. Preserve the manifest, capture/recorder behavior, current project formats, source-available license, original media and existing edit/shortcut handlers. No external script engine or MCP transport is enabled.

### Stacking and placement contract

| Scope | Token | Value |
|---|---|---:|
| Local canvas | media / ink / selection / handle / inline | 0 / 10 / 20 / 30 / 40 |
| Editor workspace | workspace / inspector / resizer | 100 / 120 / 140 |
| Application bars | chrome | 200 |
| Transient menus | menu / tool / context | 400 / 420 / 440 |
| Modal fallback | modal | 600 |

Canvas content and timeline stacking are local isolated contexts, not application-wide z-index competitors. Browser-native top layer is authoritative above document stacking: transient menus use manual Popover API when supported, native modal dialogs keep their own top-layer and focus behavior. The coordinator never moves an original menu node out of its DOM owner (delegated events, existing shortcuts, and focus order remain intact). Fixed positioning is a fallback for transient menus; unsupported inline text popovers retain the previous inline editor.

Application and workspace menus anchor to their trigger and flip above if the bottom is constrained. Tool flyouts prefer the right, flip left when needed, and clamp vertically. Context menus anchor to pointer position; text editing prompts use their existing canvas-derived position and clamp within the visible viewport. All managed overlays cap width and height and scroll internally. On small viewports a menu can overlay its anchor rather than become inaccessible. Resize, zoom/visualViewport and scroll recompute placement.

Only one transient menu may be active. Outside pointerdown dismisses it without swallowing the clicked action; Escape dismisses and restores trigger focus. A modal closes transient menus. A pending text draft is not discarded when a modal or another menu opens. Native browser dialogs (e.g. confirm, file picker, color picker) remain browser-owned and cannot be positioned by CSS. Do not add arbitrary huge z-index values or move menus into transformed canvases.

### Control registry

Extend the existing v0.7 property descriptors with explicit units, shape-specific options, image selection dimensions, and graphic transform fields. Existing source controls and edit handlers remain authoritative; contextual fields relay to them. Numeric inputs show units instead of a duplicate value. Do not claim all edits use a new transaction engine: this patch prepares descriptors for the later command/transaction work. Do not duplicate undo logic.

### Acceptance

- Node regression suite, new geometry tests, syntax checks and package integrity.
- Actual unpacked Chromium extension smoke: menus, workspace dropdown, image Shapes flyout, modal precedence, viewport bounds, pointer hit testing and Escape at 1366x768, 1024x600 and 768x600. A browser failure is a blocker, not an automatic pass.
- Manual Chrome/Edge/Firefox at all existing v0.7.1 sizes: every dropdown, context menu at all four corners, right-click/barrel-click, short-height scroll, text edit on a zoomed/panned long image, native modal focus return, rapid switching, no lost drawing or caption data, no shortcut interference during text entry. Physical Wacom and export gates remain required.
- Menu items, tool slots, prompt buttons, export dialog controls and inspector overlays should never be clipped or unreachable. Test a real imported image/video in both editors and check the last item can be scrolled into view.
- No manifest bump, release tag, updater or stable publication until release gates pass.

Future work: full dockable panel layout, central typed command/transaction engine, project model migration, composition, captions, declarative recipes and MCP. No external code is imported in this patch.
