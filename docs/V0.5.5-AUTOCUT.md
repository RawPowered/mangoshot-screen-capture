# MangoShot v0.5.5 — AutoCut local detection and ripple editing

## User journey

1. Import a finalized WebM/MP4 or open a newly recorded source in Clip Studio.
2. Click **⚡ AutoCut** in the timeline toolbar.
3. Choose **Silence (audio)** or **Still screen / inactivity**. Audio is the default only when the browser can read or scan the recording's audio track. A screen recording with no audio must use Still screen mode.
4. Adjust minimum quiet/still duration, edge padding, and audio or motion sensitivity. Keep **Protect visible titles and callouts** on unless deliberate overlap edits are needed.
5. Click **Analyze locally**. Wait for progress. No video leaves the browser. A cancellation button stops analysis between decode/seek steps.
6. Review the red timeline bands. Each candidate has a checkbox and a Preview button. Uncheck any pause that should remain.
7. Click **Ripple delete N cuts**. The approved set of edits is applied in **one non-destructive transaction**. Video clips close together with no empty timeline gaps; later graphic overlays and timeline markers shift as appropriate.
8. **Ctrl+Z** undoes the entire AutoCut batch. **Ctrl+Shift+Z** redoes it. Export is the existing real-time video-encoding flow; the original remains available via Save original.

## Detection methods and limits

### Audio silence

Tries native `AudioContext.decodeAudioData` on the entire local recording. If unsupported by the browser/container (common for video MP4), falls back to locally scanning the media element at up to three times playback speed through Web Audio. That fallback needs a user-initiated analysis click and may be refused by browser autoplay policy. There is no external service or guaranteed universal MP4 audio demuxer.

Detection is based on short-window RMS amplitude below the chosen dB threshold, not speech transcription or semantic filler-word detection. Music, fan noise, microphone noise gates, multiple voices, and quiet speech can affect suggestions. Always preview cuts before applying.

### Still-screen / inactivity

Seeks a detached, muted video element at a maximum of 900 approximate samples, measuring small-frame pixel motion. A motionless screen with important readable content can look identical to an unwanted idle period. Therefore this mode is **opt-in** and never removes content automatically without review. Analysis may be slower on long or difficult-to-seek video files; browser decoding limitations can stop the scan.

## Safety invariants

- Source file stays immutable. Cuts modify a sequence edit list, not the original recording.
- Suggestions are source-time intervals mapped into the **current** edited sequence. Previous cuts/trimmed-out source regions are never blindly deleted.
- Proposals are nonoverlapping and have small boundary padding; by default analysis protects existing visible title/callout intervals.
- The recommendation safety budget permits at most 70% of a sequence to be removed. The sequence's first and last 0.1 seconds are protected.
- All approved intervals are applied in descending sequence-time order so later cuts do not shift earlier coordinates.
- Video, graphic overlays, markers, playback position and undo/redo are updated through one existing `MangoSequenceOps.range` batch transaction.
- Any source replacement, layer timing change, or timeline edit invalidates previous suggestions; changed detection settings also require reanalysis.
- No cloud upload, telemetry, speech-to-text service or automatic irreversible deletion.

## Cross-browser test gates

- Audio with speech, intentional silences and microphone noise on Chrome/Edge/Firefox: confirm proposed timestamps align with original audio, and output playback contains no unexpected word truncation.
- WebM Opus and MP4 AAC audio tests; if audio cannot be decoded, AutoCut must explain the limitation and allow Still screen mode.
- No-audio recording: audio mode must not invent silent-removal regions; still mode should offer suggestions after motion comparison.
- Long screen recording: progress and cancellation remain responsive and memory usage bounded.
- Existing V1 razor clips + G2/G3 overlays + markers: verify proposal mapping, ripple, original-file retention, one-step undo, redo, final export playback and sound.
- Repeated analysis after manual edit/import: stale candidates never apply to a different sequence.
- Screen reader and Wacom: every suggestion can be checked and previewed with accessible buttons, independent of dragging.
