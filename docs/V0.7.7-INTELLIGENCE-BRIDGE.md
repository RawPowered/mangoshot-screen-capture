# MangoShot v0.7.7 — Intelligence Bridge (development preview)

Clip Studio only. Builds on the qualified v0.7.6 sequence engine. The extension adds optional nativeMessaging permission, requested only from the Pair button. Existing required permissions, manifest version, branding and license remain. No content-script bridge, broad host permissions, externally_connectable entry, remote cloud endpoint, automatic screen capture or arbitrary executable script.

## Architecture and boundaries

Extension page -> browser native messaging -> Python standard-library companion -> random 127.0.0.1 TCP port -> separate local MCP stdio process -> trusted MCP client. The TCP link is a private length-framed JSON protocol, not HTTP and not a public MCP endpoint. The native host runs only after explicit pairing; no service startup or persistence. Browser manifest allows only specific extension origins/Firefox ID. The host generates a 256-bit bearer secret, sends it over native messaging, and binds the first authenticated valid local client ID. The secret is shown only in the local configuration panel, not written to disk by MangoShot, never included in logs or argv. Client configuration may store it; treat it as a secret and remove expired values. Same-user malware or a compromised browser/client is outside this protection boundary. Local denial of service remains possible. No claims of hardened sandbox isolation from other processes running as the same OS user.

Three explicit scopes: metadata, sequence proposals and frame requests. All off initially. Access is current Clip Studio source only; disconnect on source reload, page close, permission revocation, explicit disconnect and 30-minute expiry. No auto-reconnect. Re-pair on client restart. Browser and host both enforce scope and request allowlists. Native and TCP messages capped at 512 KiB; recipe at 32 KiB; one request in flight, 12-second editor response deadline. The review controller has one pending request, five-minute review expiry, bounded result history and stale state checks. No request can call apply, click UI, start capture, download media, read files, execute shell or enable additional scopes.

## MCP tools

- list_commands: command catalog and sequence grammar.
- inspect_project: source and sequence durations, retained segments, graphics IDs/times/opacity, camera events and cursor counts/regions; excludes names, text, transcript, raw paths, coordinates of cursor traces and source bytes.
- propose_sequence: private draft validation, review plan and pending request ID. The client cannot approve. User reviews in Automation > Access and applies via the trusted button. Entire sequence is one undo transaction.
- request_frame: request a single frame at edited sequence time. User renders it on a separate local decoder, reviews the exact displayed JPEG, then clicks Share. Max 640x360 and bounded base64 size. No audio. Uses existing camera/transition/cursor/graphics rendering.
- request_status: polls a request ID. Pending/rejected/stale/applied status; approved frame content is delivered once, within 60 seconds. A frame may be retained by the receiving client after sharing; revocation cannot recall already delivered content.

MCP adapter implements the legacy JSON-RPC stdio handshake revisions through 2025-11-25, tools/list and tools/call. No claim of compatibility with the 2026-07-28 stateless lifecycle or every client. No SDK or third-party runtime dependency. Clients that support legacy stdio must be configured locally; cloud-only connectors cannot reach this private endpoint.

## Windows setup

1. Extract the extension preview, load unpacked in Chrome/Edge, copy its exact 32-character ID (developer mode).
2. Extract the Windows companion preview containing MangoShotBridge.exe and install-windows.ps1. Inspect the script and run from PowerShell. No administrator or execution-policy bypass required; if local policy blocks scripts, use manual per-user native host registration from official browser docs.
3. Run, for example: .\install-windows.ps1 -ChromeId <your-actual-id> (or -EdgeId for Edge, -Firefox for the current fixed Gecko ID). Both IDs can be specified; no wildcard origins. The installer copies the exe to %LOCALAPPDATA%\MangoShot\Bridge and creates HKCU native messaging registry keys. Existing registrations pointing elsewhere are refused. Companion preview is unsigned, not a production signed installer. Source is included.
4. In Clip Studio load a video, pause playback, open Automation > Intelligence Bridge, choose scopes, Pair local companion, grant optional browser permission.
5. Reveal local MCP client configuration. Replace placeholder command with absolute installed executable path, keep args ["--mcp"] and the current pairing environment values. Apply to a trusted local client that supports stdio MCP. The snippet has the common mcpServers shape; individual client settings may differ. Start/restart the MCP server process. First valid tool request binds the session.
6. Test list_commands and inspect_project; send propose_sequence or request_frame and review locally. Disconnect / revoke session when done. Remove browser permission separately if desired. Run .\install-windows.ps1 -Uninstall to remove matching current-user registrations; disconnect first. Installed executable is retained to avoid removing a host used by another browser.

For Linux/macOS development, run companion/mangoshot_bridge.py as an executable with Python 3 installed and register the native manifest in the browser's documented user-level location. Use exact extension origin(s), absolute script path and type stdio. MCP command: absolute Python interpreter, args [absolute script path,"--mcp"], env from pairing. Linux CI tests actual native messaging in Chromium. Mac/Firefox/Edge host installation needs manual qualification.

## Test gates

Core tests cover scope, no remote approval, stale/rejected/expired requests, one-shot frame disclosure, source replacement and expiry. Native test starts real host and local MCP client, exercises wrong token and second-client denial, tool discovery, proposal/frame messages and disconnect. Chromium test uses a temporary isolated extension fixture with the optional permission pre-granted to avoid UI consent automation, an exact-ID registered Python host and real generated WebM. It applies reviewed sequence, compares the actual displayed JPEG with MCP result, verifies stale rejection and disconnect. Production permission prompt still requires manual testing. Windows package build tests the executable's native and MCP pipes; actual Windows browser registration, optional prompt, Edge/Firefox, Wacom, real-user media/export and external third-party clients remain qualification gates. No system-wide mouse tracking, image/record automation or speech/AI inference is added by this bridge.
