# Bridge compatibility preview 0.7.7.1

This separate preview responds to Edge's reported error "Only permissions specified in the manifest may be requested." The original 0.7.7 source declares nativeMessaging in optional_permissions, but the earlier integration fixture changed it to a required permission before launching the browser. The exact cause on the user's local installation is not verified.

This bridge-enabled compatibility build declares nativeMessaging as a required install-time permission. It uses permissions.contains instead of an optional request for required permissions. Installation/reload must be explicitly accepted by the user. This adds no host permissions, external connections, capture APIs, or changes to approved local scopes. No companion starts until the user pairs. Session disconnect still clears all tokens and scopes; required permission cannot be revoked via the Permissions API. Disable/remove the compatibility extension or switch to the original optional build to remove the install-time capability. The optional build and main remain unchanged.

The Access panel displays the loaded build, declaration mode, and exact extension ID, and disables the remove-permission control for required permissions. The companion executable and native protocol are unchanged; reuse the prior Windows package. Save/export current work before reloading the extension. Keep the same unpacked directory/extension ID to preserve the native host registration. Verify actual Windows browser behavior manually. The browser integration test now uses the shipping manifest byte-for-byte, with no injected permission.

Numeric manifest version stays 0.6.18 to preserve the preview pipeline; version_name identifies the hotfix in Chromium.
