# Recording integrity recovery

User reported a 53–63 second capture represented as 0.05 seconds in Clip Studio (616 cursor samples). Evidence proves the editor loaded an anomalously short source, not whether the original file has missing packets. Recorder previously drove compositing from document requestAnimationFrame. This preview attempts native Chromium MediaStreamTrackProcessor / MediaStreamTrackGenerator output with a bounded single-frame reader, worker-driven tick, repeated static frames, and monotonic timestamps; a canvas fallback uses the same worker clock with explicit requestFrame when available. Existing annotation/camera/cursor compositing and audio mixing are retained; source switching retains the stable encoder track. Fallback remains browser-dependent. Submitted frame counts are not encoded-frame counts. Record elapsed and frame stats in local clip/recovery metadata; compare decoder length against capture clock or trace tail. Unknown/suspicious media probes actual endpoint. Do not invent duration, and do not create an editable timeline on a substantial discrepancy. Save original remains available. Existing damaged video is not automatically remuxed or claimed recoverable. UI: primary lane first, fractional ruler for subsecond sources, compact property tabs, cursor modal and Smart Zoom dials, persistent source check banner. Full UI redesign and physical Windows screen/monitor test remain outstanding. Qualification: real synthetic 55-second recording with document rAF disabled, ffprobe duration and decoded distinct early/late frames, handoff, primary track, dials, and short mismatch rejection; existing monitor switch and regression gates.
