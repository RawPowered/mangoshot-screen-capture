# MangoShot Automation Studio v0.7.5 — preview contract

Based on qualified Cursor Director v0.7.4. A shared native-modal workspace is accessible from Automation in both editor menu bars and from Record Studio transport. It exposes a searchable registry, JSON editor, review console, current context, local recipe library, session history and access boundaries. The existing editor menus/shortcuts remain authoritative. No new manifest permissions, native bridge, network listener, remote execution, arbitrary JS or release version bump.

## 15 initial commands

Image: layer opacity, translate, style, duplicate, visibility and lock. Explicitly target the selected ordinary layer; redaction/eraser edits are excluded. Locked layers cannot be edited except explicit unlock. Source-pixel translation. Video: graphic add/opacity, ripple-delete range, camera zoom range, cursor effects add/update/remove and Smart Zoom. Record: live cursor configuration. No capture start, tab consent, path retention, file system, clipboard, export or shell commands.

Recipes are single-command JSON envelopes with schema mangoshot.automation.recipe.v1, command and args. Strict typed allowlist, nested field/range validation, 16 KiB limit. Example:

~~~json
{"schema":"mangoshot.automation.recipe.v1","command":"clip.cursor.smartZoom","args":{"mode":"auto","scale":2,"transition":0.4,"hold":1.2,"limit":8}}
~~~

Preview makes no edits. A bounded single-use ticket ties the validated plan to the current studio source identity, revision and state (including selected layer or relevant timeline). The ticket expires after five minutes. Apply rechecks state before calling the existing editor operation. Editing the recipe, closing the dialog or leaving the recipe tab cancels review. Existing image/video edits use one undo snapshot or grouped camera/cursor transaction. Recorder config changes only future frames; cannot undo already encoded video. Existing legacy recipe panels remain available; they are not yet migrated to the shared dispatcher. No arbitrary multi-command transaction or universal undo engine is claimed. Review shows proposed data changes rather than a rendered sandbox video. Smart Zoom preview applies the whole proposed bounded batch; individual candidate selection remains in Cursor Director.

Recipes can be saved, replaced, loaded, imported/exported and deleted; the library is shared across extension pages, stores up to 40 recipes and rejects cross-studio execution. It may contain user-entered text; export/share intentionally. Session history is capped at 100 and logs command/status/time only, no media or script payload. No persistent audit trail is claimed.

## MCP adapter contract (design only, no exposed server)

Future local companion should map MCP tools to the registry rather than browser clicks. Read-only tools: list_commands (catalog with field definitions), inspect_context (explicitly scoped metadata, not media bytes), validate_recipe/preview_recipe (no mutation). Write: request_apply_review (requires user approval in the active studio and a current single-use ticket). The local extension API MangoAutomationV075 is an in-page integration surface for packaged code, not a public endpoint or security boundary against compromised extension code. External transport must not call apply directly without UI authorization.

Before native messaging or a local MCP transport: require explicit session pairing, per-studio/project scope, revocation, origin/extension ID validation, least privilege, replay and stale-ticket rejection, audit policy, no arbitrary executable payloads, no remote network exposure by default, and tested disconnection/timeout behavior. Do not add permissions before the companion architecture is qualified.

## Validation

Unit gates cover invalid commands/args/prototypes, bounds, wrong studio, preview purity, stale source/revision, expired/replayed/canceled tickets, library and history. Existing Clip Studio model tests exercise actual graphic, camera and ripple transactions with undo; browser smoke opens real extension pages, checks modal bounds, empty editor rejection, recorder settings preview/apply and local library. Physical image gesture, actual capture, real encoded-video output, Firefox/Edge and full workspace docking remain manual/future gates. Main/manifest/licensing stay unchanged.
